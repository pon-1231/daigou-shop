# 我會怎麼「訓練自己」用 ICT 交易黃金

> 這份文件回答的是：**在不靠運氣的前提下，一個 AI + 一個人要用什麼流程，
> 把 ICT 這套很模糊的東西，逼成一個可以被測量、被證偽、被逐步改善的系統。**

---

## 0. 先把實話講在前面

我必須先講清楚三件事，否則後面所有東西都是騙人的：

1. **「穩定獲利」不是一個可以被保證的目標。** 能被工程化的只有一件事：
   *把一個有統計優勢的流程，用小到不會讓你出局的風險，重複執行夠多次。*
   結果依然是機率分佈，不是承諾。

2. **ICT 本身不是公式，是一套敘事框架。** 它的語言（「等流動性被掃」「等位移」
   「在折價區進場」）之所以讓人覺得「看圖都對」，正是因為它夠模糊，事後總能找到
   一個符合的解讀。**模糊 = 不可證偽 = 不能訓練。** 所以第一步永遠是翻譯成定義。

3. **我不是靠「看很多圖變得有盤感」來訓練的。** 我沒有直覺，也不該假裝有。
   我能做的是另一件事，而且這件事人類做起來很痛苦、我做起來很便宜：
   **把規則寫死 → 在幾十萬根 K 棒上測量 → 把沒有統計支撐的部分砍掉。**

所以這份「訓練計畫」的本質是：**用測量取代盤感。**

---

## 1. 第一步：把 ICT 的話翻譯成可測量的定義

不可測量的東西一律刪掉。以下是這個專案實際採用的翻譯表：

| ICT 的說法 | 本專案的可測量定義 | 位置 |
|---|---|---|
| 流動性（liquidity） | 前擺動高/低、相等高低點、前日高低、亞洲/倫敦盤高低 | `state.py` `LiquidityPool` |
| 流動性被掃（sweep） | K 棒**影線穿過**價位、但**收盤回到內側** | `state.py` `_update_pool_state` |
| 被吃掉（run / consumed） | 收盤**直接穿過**價位 → 這不是掃，是突破，不可進場 | 同上 |
| 結構轉變（MSS / CHoCH） | 收盤突破最近一個**未被破壞**的擺動點，且方向與原趨勢相反 | `state.py` `_detect_structure` |
| 順勢突破（BOS） | 同上，但方向與原趨勢相同 | 同上 |
| 位移（displacement） | 造成突破的那段腿**留下 FVG** 且幅度 ≥ 1 ATR | `_is_displacement_leg` |
| 公允價值缺口（FVG） | 三根 K：第 3 根的低 > 第 1 根的高（多方） | `_detect_fvg` |
| 訂單塊（OB） | 位移腿開始前**最後一根反向收盤** K 棒 | `_build_order_block` |
| 折價／溢價 | 當前交易區間的 50% 為均衡點，之下折價、之上溢價 | `DealingRange` |
| OTE | 該段腿的 0.62–0.79 回撤 | `pipeline.py` `stage_pd_array` |
| 殺戮時段（killzone） | 紐約當地時間的固定視窗，**含日光節約時間** | `sessions.py` |
| 日內方向（draw on liquidity） | 同向最近、且在 ATR 可達範圍內的未觸及流動性池 | `draw_on_liquidity` |

**這張表就是全部的「主觀」所在。** 一旦定死，後面每一個結論都是算出來的，不是講出來的。
你如果日後覺得某個定義不對（很可能會），改這張表比改任何參數都重要。

## 2. 資料層：訓練的地基（最容易出錯、也最致命）

### 2.1 需要什麼
- **XAUUSD M1 或 M5，至少 3–5 年。** 少於 2 年會導致樣本數不足以下任何結論。
- 一份可靠的**經濟數據日曆**（NFP / CPI / FOMC），用來標記黑名單時段。

### 2.2 第一個殺手：時區
大部分零售黃金資料是 **broker time（常見 UTC+2／+3）**，不是 UTC。
如果你當成 UTC 讀進來，**每一個 killzone 都會平移 2–3 小時**——
回測結果看起來像個策略結論，其實只是一個時鐘 bug。

```bash
# 一定要指定來源時區，然後人工核對一次已知的倫敦開盤
python3 -m ictgold backtest --csv xauusd_m5.csv --tz Europe/Athens
```

### 2.3 三段切分，而且 holdout 要真的鎖起來
```
2019 ─────── 2022 │ 2023 ─── 2024 │ 2025 ───────
   訓練 (train)   │  驗證 (valid) │ 封存 (holdout)
   隨便試          │  walk-forward │ 全部定案後只跑一次
```
**封存段只能跑一次。** 跑第二次它就變成驗證段了，你就沒有乾淨的樣本了。
這條紀律比任何參數都值錢。

### 2.4 成本要先建模，不是事後扣
點差、進場滑價、**停損滑價（更大）**、手續費。本專案預設對黃金取偏保守值。
這件事的重要性在第 4.3 節會用一個真實例子說明。

## 3. 三層架構：分清楚哪些能調、哪些不能

| 層 | 內容 | 能不能調 | 數量 |
|---|---|---|---|
| **L1 規則層** | 「掃流動性 → 結構轉變 → 折價區進場」的**順序與邏輯** | ❌ 不調。改這層等於換策略，全部重跑 | — |
| **L2 參數層** | ATR 倍數、回看根數、最小 R:R … | ✅ 用 walk-forward 調 | **要少到能數出來** |
| **L3 評分層** | confluence 權重 | ✅ 但要用歷史成果**回歸擬合**，不是憑感覺 | 8 個權重 |

### 參數預算：這是防過擬合的第一道防線
規則很簡單：**每個可調參數，至少要有 30–50 筆交易來支撐它。**

本專案實際會動的參數大約 8 個 → 需要 **240–400 筆交易**。
以這個模型的選擇性（約每年 60–120 筆），代表你至少需要 **3 年資料**才有資格開始調參。

> 如果你發現自己在調第 15 個參數，你已經不是在訓練策略，是在描圖。

## 4. 訓練迴圈：實際怎麼做

### Step 0 — 建立 baseline
用預設設定跑一次，記下數字。**之後每一次改動都必須跟它比。**
沒有 baseline 的「改善」是幻覺。

### Step 1 — 先看策略「死在哪」，而不是看損益
```
PIPELINE VETOES (where setups died)
time                 12454   81.4%
structure              981    6.4%
liquidity              769    5.0%
bias                   480    3.1%
```
這張表是整個系統最被低估的部分。它告訴你：
- 某個 setup **完全不觸發** → 條件互相矛盾，是 bug 不是策略
- 某一關卡掉 99% → 那個條件可能過嚴，先確認它有沒有換來更好的期望值
- 交易數太多 → 條件過鬆，你在交易雜訊

### Step 2 — 分群統計，然後動刀
報告會自動輸出 **依 setup / killzone / 星期 / 出場原因 / 分數** 的分組表。
做法是：**砍掉沒有統計支撐的分支，而不是優化它。**

```
BY SETUP              n     win%   exp(R)     PF
judas_reversal       13    23.1%   -0.184   0.77
ote_continuation     29    20.7%   +0.147   1.17
silver_bullet        12    16.7%   -0.543   0.19
```
但注意 n=12 的分支**什麼都證明不了**。報告裡的 `sample needed` 會直接算給你：
以你的期望值和波動，要幾筆交易才能讓這個結論脫離雜訊。
**先看 n，再看 win%。** 順序反過來就是大部分人虧錢的原因。

### Step 3 — 用 MAE / MFE 調停損停利，不要憑感覺

這是把「感覺停損太緊」變成數字的方法：

- **MAE（最大逆行）分佈**：把**最終獲利的單**拿出來，看它們最多逆行多少 R。
  如果 90% 的贏單 MAE < 0.6R，那你的停損可以縮到 0.7R，多出來的空間是白給的。
- **MFE（最大順行）分佈**：把**最終虧損的單**拿出來，看它們最多跑多遠。
  如果一半的輸單曾經跑到 +1.5R，那「+1R 保本」就是有數據支撐的規則，
  而不是一個聽起來很安全的習慣。

本專案每筆交易都會記錄 `mae_r` / `mfe_r`，就是為了這一步。

### Step 4 — Walk-forward 驗證（唯一算數的成績）
```bash
python3 -m ictgold walkforward --csv xauusd_m5.csv --tz Europe/Athens --folds 5
```
只在 IS 段調參，只用 OOS 段評分，OOS 段互不重疊、串起來就是一份連續的
**樣本外成績單**。**通過門檻建議：`OOS 期望值 > 0.5 × IS 期望值`。**
掉超過一半 = 你調的是雜訊。

### Step 5 — Monte Carlo 決定風險大小
打亂交易**順序**（不是結果）跑幾千次，看回撤分佈：
```
median drawdown   : 11.3 R
95th pct drawdown : 14.7 R   <- 用這個數字決定倉位
```
你實際經歷的那條曲線只是這個分佈裡的一抽，而且通常比中位數幸運。
**用 p95 回撤決定單筆風險**：若你最多能忍受 -20%，而 p95 回撤是 15R，
則單筆風險上限 = 20% / 15 ≈ **1.3%**。這是算出來的，不是喊出來的。

### Step 6 — 封存段，只跑一次
定案後跑 holdout。掉太多就回去改 **L1 規則層**（假設錯了），不要回去微調參數。

## 5. 反過擬合的紀律（寫下來，因為人一定會作弊）

1. **參數要能數出來。** 超過 10 個就砍。
2. **每次調整都要有機制解釋。** 「把回看從 24 改成 26，績效變好」→ 不接受。
   「停損必須大於 4 倍來回摩擦成本，否則 -1R 實際上是 -1.6R」→ 接受。
3. **不准在封存段迭代。**
4. **記實驗日誌。** 每次改了什麼、為什麼改、baseline 對比。
   沒有日誌，你三個月後會忘記為什麼是這個數字，然後開始亂改。
5. **改定義 > 改參數。** 效果最大的改動幾乎都在第 1 節那張表裡。

---

## 6. 事前定義「什麼情況算失效」

這一節要在**上線前**寫好，因為虧錢的時候人是寫不出這個的：

- 連續虧損筆數 **超過 Monte Carlo p95** → 停手，重新驗證
- 滾動 50 筆的期望值 **< 0** 且持續兩個月 → 停手
- 實盤滑價 **持續大於回測假設的 1.5 倍** → 成本模型錯了，全部重算
- 連續 3 個月交易筆數 **低於回測頻率的一半** → 市場結構變了，模型不再適用

## 7. 上線節奏（不要一步到位）

| 階段 | 期間 | 風險 | 通過條件 |
|---|---|---|---|
| 紙上模擬 | 2 個月 | 0 | 實際訊號與回測訊號一致率 > 90% |
| 極小倉 | 2 個月 | 0.1× | 滑價符合假設 |
| 小倉 | 3 個月 | 0.25× | 期望值仍為正 |
| 正常倉 | — | 0.5–1× | 通過以上全部 |

紙上模擬階段最重要的不是賺賠，是**對帳**：實盤訊號跟回測訊號對不起來，
代表你的引擎跟現實之間有 bug，這比虧錢嚴重得多。

## 8. 現實的數字長什麼樣

一個**真的能用**的 ICT 日內黃金模型，長得比較像這樣：

| 指標 | 合理範圍 | 說明 |
|---|---|---|
| 勝率 | **35–50%** | 追求高勝率會逼你縮停利，反而殺死期望值 |
| 賠率 (payoff) | 2.0–3.0 | 靠這個賺錢，不是靠勝率 |
| 期望值 | **+0.1 ~ +0.3 R** | 超過 0.5R 請先懷疑有前視偏差 |
| 年交易數 | 60–150 | 太多代表條件太鬆 |
| 最大回撤 | 10–20 R | 一定會發生，先算好再上 |

> **如果你的回測顯示 70% 勝率、期望值 0.8R，最可能的解釋不是你找到聖杯，
> 而是資料洩漏。** 優先去查：擺動點有沒有提前公佈、HTF 有沒有餵進未走完的 K 棒、
> 訊號當根有沒有成交。本專案的測試檔就是專門在鎖這三件事。

「穩定」是**月／季**尺度的概念。以 45% 勝率來說，連輸 6 筆的機率超過 2%，
在 100 筆交易裡幾乎一定會遇到。那不是策略壞了，那是策略正常運作的一部分。

## 9. 分工：我能做什麼、不能做什麼

**我能做的（而且很便宜）**
- 把模糊規則變成可執行定義
- 在幾十萬根 K 棒上跑上千次測量
- 抓出前視偏差 / 時區 bug / 成本假設錯誤（這些人眼幾乎看不出來）
- 做統計檢定，告訴你「這個結論的樣本夠不夠」

**我不能做的（不要指望）**
- 判斷宏觀語境（戰爭、央行轉向、實體需求）
- 判斷某根 K 棒「感覺不對」
- 承擔你的風險，或替你決定能忍受多少回撤

**關於你說「交易知識不夠」** —— 這其實不是這個專案的阻礙，反而是它的用途。
你不需要先變成專家才能開始。`explain` 指令會把每一個 setup 每一關的通過／否決
理由印出來：

```bash
python3 -m ictgold explain --csv xauusd_m5.csv --at 2024-06-03T13:35:00+00:00
```
```
--- judas_reversal ---
  [PASS] time       in ny_am on Mon
  [PASS] bias       htf trend=bullish; htf discount (0.31); mtf aligned
  [PASS] liquidity  swept asia_low @ 2321.40
  [VETO] structure  no CHOCH bullish in last 12 bars
```

**這就是課程本身。** 你每天看幾次這個輸出，一個月後你對「為什麼這裡不能進」
的理解，會比看幾十小時影片紮實得多——因為它是具體的、當下的、可反駁的。
而當你開始覺得「這裡它否決錯了」，你就有能力去改第 1 節那張定義表了。
**那才是真正的訓練，而且訓練的是你，不只是模型。**
